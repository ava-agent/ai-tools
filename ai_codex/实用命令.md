# Codex CLI 实用命令

> 完整的 Codex CLI 命令参考和与 Claude Code 对标

## 📋 与 Claude Code 命令对标

| Claude Code | Codex CLI | 说明 |
|-------------|-----------|------|
| `--permission-mode plan` | `codex -a on-failure` | 规划 + 执行，失败时询问 |
| `--dangerously-skip-permissions` | `codex --full-auto` | 自动执行（有沙箱保护） |
| 完全跳过权限 | `codex --dangerously-bypass-approvals-and-sandbox` | 极致自动（无保护） |
| `--continue` | `codex resume --last` | 继续上次会话 |
| `@filename` | `codex -C /path/to/file` | 文件引用 |

## 🎯 权限模式详解

### 1. 自动执行模式（对标 Claude Code）

```bash
# Claude Code
claude --dangerously-skip-permissions --permission-mode plan

# Codex CLI（最接近）
codex -a on-failure --sandbox workspace-write

# 说明：
# - on-failure: 自动执行，失败时询问
# - workspace-write: 沙箱保护，仅工作区可写
```

### 2. 推荐的自动模式

```bash
# 全自动模式（推荐，有沙箱保护）
codex --full-auto "格式化所有文件"

# 等同于
codex -a on-request -s workspace-write "格式化所有文件"

# 说明：
# - on-request: 模型自行决定何时询问
# - workspace-write: 仅工作区可写
```

### 3. 完全自动化

```bash
# 从不询问，有沙箱保护
codex -a never -s workspace-write "重构代码"

# 失败时才询问
codex -a on-failure -s workspace-write "运行测试"

# 危险模式：无沙箱、无确认（仅隔离环境）
codex --dangerously-bypass-approvals-and-sandbox "系统配置"
```

### 审批策略对比

| 策略 | 命令 | 说明 | 安全性 |
|------|------|------|--------|
| **untrusted** | `-a untrusted` | 只运行受信任的命令 | ⭐⭐⭐ |
| **on-failure** | `-a on-failure` | 失败时询问 | ⭐⭐ |
| **on-request** | `-a on-request` | 模型决定何时询问 | ⭐⭐ |
| **never** | `-a never` | 从不询问 | ⚠️ 谨慎使用 |

## 🛡️ 沙箱模式详解

> **沙箱保护**是指限制 Codex CLI 可以执行的操作范围，防止意外修改系统文件或执行危险命令。

### 沙箱模式对比

| 模式 | 命令 | 可写范围 | 执行限制 | 安全性 |
|------|------|---------|---------|--------|
| **read-only** | `-s read-only` | ❌ 无 | 仅读取命令 | ⭐⭐⭐ |
| **workspace-write** | `-s workspace-write` | ✅ 工作区 | 安全命令列表 | ⭐⭐ |
| **danger-full-access** | `-s danger-full-access` | ✅ 整个系统 | ⚠️ 无限制 | ⚠️ 危险 |

### 只读模式（最安全）

```bash
codex -s read-only "分析代码结构"

# 可以执行：
# - ls, cat, grep 等读取命令
# - 代码分析
# - 文档生成

# 不能执行：
# - 写入文件
# - 删除操作
# - 安装依赖
# - 运行测试
```

### 工作区写入模式（推荐）

```bash
codex -s workspace-write "修复 bug"

# 可以执行：
# - 修改工作区文件
# - 运行安全命令（npm test, npm run build）
# - 创建新文件
# - Git 操作

# 不能执行：
# - 修改系统文件（/etc, /usr 等）
# - 删除工作区外的文件
# - 危险命令（rm -rf, dd 等）
```

### 完全访问模式（危险）

```bash
codex -s danger-full-access "系统配置"

# 可以执行：
# - 任何命令
# - 修改系统文件
# - 安装全局包
# - 修改环境变量

# ⚠️ 仅在以下情况使用：
# - Docker 容器中
# - 虚拟机中
# - 完全隔离的环境
```

## 💡 推荐组合

### 日常开发

```bash
# 代码审查（只读）
codex review -s read-only

# 快速修复（自动执行）
codex --full-auto "修复 lint 错误"

# 功能开发（有保护）
codex -a on-failure -s workspace-write "实现新功能"
```

### 重要操作

```bash
# 先分析（只读）
codex -s read-only "分析重构影响"

# 再执行（询问确认）
codex -a untrusted -s workspace-write "执行重构"

# 审查变更
codex apply
git diff
```

### 快速任务

```bash
# 格式化代码
codex -a never -s workspace-write "格式化所有文件"

# 生成文档
codex -a never -s read-only "生成 API 文档"

# 运行测试
codex -a never -s workspace-write "运行测试套件"
```

## 🚨 安全最佳实践

### 1. 总是在 Git 仓库中

```bash
# 检查状态
git status

# 创建分支
git checkout -b codex-work

# 执行操作
codex --full-auto "执行操作"

# 审查变更
git diff
```

### 2. 先用只读模式测试

```bash
# 第一步：分析（只读）
codex -s read-only "分析重构影响范围"

# 第二步：规划
codex -s read-only "制定详细重构计划"

# 第三步：执行（有保护）
codex -a on-failure -s workspace-write "执行重构"
```

### 3. 审查变更

```bash
# 应用变更
codex apply

# 查看差异
git diff

# 如有问题，立即回滚
git checkout .
```

### 4. 使用配置文件

```bash
# 编辑配置
# Linux/macOS
nano ~/.codex/config.toml

# Windows
notepad %USERPROFILE%\.codex\config.toml

# 设置默认沙箱模式
# ~/.codex/config.toml
sandbox = "workspace-write"
ask_for_approval = "on-failure"
```
